ユーザインターフェース

User Interface ／ UI

人とコンピュータ(機器)が情報をやりとりする「接点」のこと。人から機器へ伝えるのが入力、機器から人へ伝えるのが出力です。

まずは身近な例で見てみよう

場面を選ぶと、「入力」と「出力」が順番に動きます(自動で進みます)。右の手順をタップすると、その場面へ移動できます。

    POINT

    UIは「見た目のデザイン」だけではありません。入力の方法と出力の方法をひとまとめにした、人と機器のやりとりの仕組み全体のことです。

    アフォーダンス

    Affordance ／ モノが人に与える行為の可能性

    アフォーダンスとは、モノが人に対して「〜できる」という行為の可能性を与えていること。英語の afford(与える・提供する)から作られた言葉で、心理学者のジェームズ・ギブソンが提唱し、のちにドナルド・ノーマンがデザインの分野に広めました。

    ポイントは、可能性はモノ自体にあるが、人が気づけるとは限らないということ。気づけない可能性は、使われないか、使い間違えられます。

    モノアフォーダンス(できること)気づかせる手がかり(=シグニファイア)
    いす座れる座面の高さ・平らな形
    取っ手つかめる手にちょうどよい棒の形
    ボタン押せる出っ張り・影・色
    スマホの画面タップできる角丸の枠・影・色付きの文字

    実験:ガラスの壁の「通れない」に気づける?

    ガラスの壁には「通れない」という性質(アフォーダンス)がありますが、透明なので気づけません。シールが手がかり(シグニファイア)になります。

    アフォーダンス

    シグニファイア
    POINT

    アフォーダンスはモノの側にある可能性です。でも、人がそれに気づけなければ、使われなかったり使い間違えられたりします。その「気づかせる手がかり」が、次のページのシグニファイアです。

    シグニファイア

    Signifier ／ 操作のための手がかり

    モノや画面が、「どこを・どう操作すればよいか」を利用者に伝える手がかり(合図・目印)のこと。取っ手の形、ボタンの立体感、矢印、色、文字などがあたります。

    アフォーダンス と シグニファイア

    Affordance ／ Signifier
    アフォーダンス
    モノが持つ「〜できる」という行為の可能性
    例:扉は「開けられる」
    → 気づかせる
    シグニファイア
    その可能性を人に知らせる目印
    例:取っ手の形、「押」の文字
    アフォーダンスシグニファイア
    ひとことでモノが持つ「〜できる」という可能性その可能性を人に知らせる手がかり
    どこにある?モノそのものの性質見た目・形・文字・音など、人が感じ取れる合図
    ガラスの壁通り抜けられない衝突防止のシール
    扉開けられる取っ手の形、「押」の文字
    スマホの画面タップできるボタンの枠・影・色
    POINT

    「できることそのもの」ならアフォーダンス、「できることに気づかせる目印」ならシグニファイア。使い方がわかりにくいときは、アフォーダンスがなくなったのではなく、シグニファイアが足りないことが多いのです。

    ユニバーサルデザイン

    Universal Design ／ UD

    年齢・性別・国籍・障害の有無などに関係なく、できるだけ多くの人が使えるように、最初から設計するという考え方。アメリカの建築家ロナルド・メイス(1985年)が提唱しました。

    バリアフリーとの違いは「いつ」考えるか

    バリアフリー▶設計▶完成・利用開始▶障壁に気づく▶あとから取り除く(例:段差にスロープ)
    ユニバーサルデザイン▶最初から「みんな」を想定して設計(例:段差のない入口)▶完成・利用開始

    ユニバーサルデザイン

    Universal Design ／ UD

    ユニバーサルデザインの7原則

    1

    公平な利用

    誰でも同じように使え、使いにくい人をつくらない。

    例:自動ドア
    2

    利用における柔軟性

    使う人の好みや能力に合わせて使い方を選べる。

    例:右利きにも左利きにも使えるはさみ
    3

    単純で直感的な利用

    経験や知識がなくても、使い方がすぐわかる。

    例:ピクトグラム(絵記号)
    4

    認知しやすい情報

    必要な情報が、見えにくい・聞こえにくい人にも伝わる。

    例:音・光・文字で知らせる駅の案内
    5

    間違いに対する寛大さ

    うっかりミスが、危険や大きな失敗につながらない。

    例:「元に戻す」機能
    6

    身体的な負担が少ない

    無理な姿勢や強い力がなくても、楽に使える。

    例:レバー式のドアハンドル
    7

    接近して使える寸法と空間

    体格や姿勢、移動手段に関わらず、近づいて使える。

    例:幅の広い改札
    共通する考え方: 「みんな」の中の一人ひとりの違いを、最初から想定する。

    実験:色の見え方が違う人には、どう見える?

    色の見え方には個人差があります(日本人男性の約20人に1人、女性の約500人に1人)。簡易シミュレーションで、2つの運行情報を見比べよう。

    △ 色だけで区別している

    A線
    B線
    C線

    緑=平常 / 橙=遅れ / 赤=運休

    ○ 色 + 形 + 文字で区別している

    ○A線平常運転
    !B線遅れあり
    ×C線運休

    色が違って見えても、形と文字で伝わる

    ※ 見え方の個人差は大きく、これは目安となる簡易シミュレーションです。

    POINT

    「色だけ」に頼らず、形・文字・音・位置も使って伝える(原則4)。これは、色の見え方が違う人だけでなく、明るい屋外や白黒印刷など、すべての人の助けになります。

    ユーザビリティ

    Usability ／ 使いやすさ

    特定の利用者が、特定の場面で、目的を効果的に・効率よく・満足して達成できる度合い(使いやすさ)。国際規格(ISO 9241-11)では、次の3つの視点で考えます。

    効果

    目的を最後まで達成できたか。

    例:注文を完了できる

    効率

    かかった手間や時間はどれくらいか。

    例:少ない手順で購入できる

    満足度

    使っていて快適か、不快でないか。

    例:迷わず気持ちよく使えた

    実験:同じ商品を買うのに、何手かかる?

    2つの通販サイトで、同じ商品を購入するまでの手順を見てみよう(自動で進みます)。

    ユーザビリティを高める工夫

    手順を減らす入力例を見せる間違いを元に戻せるボタンの形や位置をそろえる用語をやさしくする
    POINT

    ユーザビリティは「その人が、その場面で、使いやすいか」を問います。使えるけれど不便、迷う、疲れる、といった問題は、ユーザビリティの問題です。

    アクセシビリティ

    Accessibility ／ 利用しやすさ・近づきやすさ

    年齢や障害の有無、使う機器や環境に関わらず、情報やサービスを利用できる度合い。「そもそも使えるか」を問います。

    見る

    見えにくい・見えない人にも。

    画像に代替テキスト／十分な色の差

    聞く

    聞こえにくい人にも。

    動画に字幕／音声に文字起こし

    操作する

    マウスが使えない人にも。

    キーボードだけで操作できる

    理解する

    だれにでも伝わるように。

    やさしい言葉／ふりがな／図

    「使う機器(スマホ・古いパソコン)」や「環境(電波が弱い、屋外の明るい場所)」でも使えるかどうかも、アクセシビリティです。

    実験:画像の代替テキストがあると?

    目が見えない人は、読み上げソフト(スクリーンリーダー)で画面の内容を音声で聞きます。

    読み上げソフトの声

    POINT

    アクセシビリティは「使える人・場面の幅」を問います。ひとつでも「使えない人」がいると、アクセシビリティが低い状態です。

    両者は無関係ではなく、アクセシビリティが「入口」、ユーザビリティが「入ってから」と考えるとつかみやすいです。どちらの問題か迷う例もあるので、「そもそも使えない?」→アクセシビリティ、「使えるけど不便?」→ユーザビリティ、と考えてみよう。

    フェイルセーフ

    Fail-safe ／ 故障しても安全に

    機械やシステムに故障・異常が起きても、安全な側に働くようにする設計。「壊れること」を前提に、被害を小さくします。

    フェイルセーフ故障しても安全に

    例:踏切の遮断機。電力が切れたら、どうなる?

    ボタンを押して、電力が切れた瞬間を見てみよう。

    故障が起きると「遮断かんが下りる(=危険な踏切に入れない)」ほうへ倒れる設計。もし上がったまま止まる設計なら、故障が事故につながります。

    身近なフェイルセーフ

    踏切の遮断機
    停電すると、遮断かんが自分の重みで下りる
    エレベーター
    ワイヤーが切れても、非常止め装置でカゴが落ちない
    ブレーカー
    電流が大きすぎると、自動で電気を止める

    どれも「壊れた・異常が起きた」ときに、危険が広がらない方向へ働きます。

    POINT

    フェイルセーフは機械やシステムの故障への備えです。「故障はいつか起きる」と考えて、そのときの状態が安全になるように設計します。

    フールプルーフ

    Fool-proof ／ 間違えても安全に

    人が操作を間違えても、危険が起きない・間違えられないようにする設計。うっかりや思い込み(ヒューマンエラー)への備えです。

    フールプルーフ間違えても安全に

    例:カードの切り欠き。逆向きに挿すと、どうなる?

    切り欠きが合わないと、そもそも最後まで入りません。

    「間違えたら壊れる・危ない」のではなく、間違いそのものが起きにくい/起こせない形にする設計。ほかにも、給油ノズルの口径違い、削除前の確認画面などがあります。

    身近なフールプルーフ

    電子レンジ
    扉が開いていると、加熱が始まらない
    給油ノズル
    軽油用とガソリン用で太さが違い、入れ間違えられない
    確認ダイアログ
    削除の前に「本当に削除しますか?」と確認する
    カード・端子
    切り欠きがあり、逆向きに挿せない

    どれも、間違いを「起こしにくく」「起こせなく」しています。

    POINT

    フールプルーフは人の操作ミスへの備えです。「人は間違える」と考えて、間違えても大丈夫な(間違えられない)形にします。

    フェイルセーフ と フールプルーフ

    Fail-safe ／ Fool-proof
    フェイルセーフ
    機械やシステムに故障・異常が起きても、安全な側に働くようにする設計
    原因が
    ちがう
    フールプルーフ
    人が操作を間違えても、危険が起きない・間違えられないようにする設計
    フェイルセーフフールプルーフ
    想定する原因機械・部品・システムの故障、異常、停電人の誤操作・うっかり(ヒューマンエラー)
    考え方壊れても、安全な側へ動く間違えても危険にならない/間違えられない
    例停電で遮断機が下りる、エレベーターの非常止め装置扉が開いていると動かない電子レンジ、切り欠きのある端子、確認ダイアログ
    POINT

    迷ったら 「何が起きたときの備え?」 と考えよう。機械が壊れたときならフェイルセーフ、人が間違えたときならフールプルーフ。安全な製品は、両方を組み合わせています。
