サーバ

サービスを提供するのがサーバ、利用するのがクライアント。「要求」と「応答」でやりとりする。

たのむ側と、こたえる側

常に稼働していて、要求に応じてサービスを提供するシステムをサーバとよびます。一方、サーバにサービスを要求し、利用するシステムをクライアントとよびます。サーバとクライアントの間のやりとりでサービスを実現する方式を、クライアントサーバ型とよびます。インターネットに接続されたサーバとの通信によって、多くのサービスが実現されています。

考えてみよう：
スマホでWebページを見ているとき、クライアントとサーバはそれぞれどれ？

スマホのWebブラウザがクライアント、ページのデータを返すWebサーバがサーバです。英語の server は「サービスを提供するもの」、client は「依頼する人」という意味です。

サーバ

サーバに集まってやりとりするか、端末どうしで直接やりとりするか。

クライアントサーバ型とピアツーピア型

サーバを置かず、ネットワークに接続している端末どうしが対等の立場でつながり、直接データをやりとりする方式をピアツーピア型(peer to peer、P2P)といいます。peer は「仲間・対等な相手」という意味です。

クライアントサーバ型ピアツーピア型
役割サーバ(提供する)とクライアント(利用する)に分かれるどの端末も対等。提供も利用もする
情報の管理サーバにまとめて管理できる情報が端末に散らばる
1台が止まるとサーバが止まると、全員が使えないほかの端末どうしで続けられる
例Webページ、電子メール、ネット予約一部のファイル共有ソフトや通話アプリ
考えてみよう：
コンサートのチケット予約に、クライアントサーバ型が向いているのはなぜ？

席の空き状況を、サーバで1か所にまとめて管理する必要があるからです。どの端末から見ても同じ情報になり、同じ席を2人に売ってしまうことも防げます。お店のレジ(POSシステム)や交通系ICカードも、サーバが情報をまとめて管理しています。

電子メール

メールは、自分のメールサーバ → 相手のメールサーバ → メールボックス、とリレーされる。

メールサーバがリレーして届ける

電子メールの宛先であるメールアドレスは、メールサーバのドメイン名とユーザ名を「@」でつないだ形をしています。作成したメールは、メールクライアントとよばれるソフトウェアによって、まず自分のメールサーバに送られます。そこから宛先のメールサーバに転送され、メールボックスという場所に保存されます。受信者はメールクライアントで自分のメールボックスを確認し、メールを受け取ります。

考えてみよう：
相手のパソコンの電源が切れているときに送ったメールは、どうなる？

相手のメールサーバのメールボックスに保存されて待っています。メールサーバは常に稼働しているので、受信者があとでメールクライアントを開けば受け取れます。右の図で、受信者のパソコンを「電源OFF」にして確かめてみよう。

電子メール

送るときは SMTP。受け取るときは POP か IMAP。

送る約束と、受け取る約束

メールの送信や、メールサーバどうしの転送にはSMTP、メールボックスからの受信にはPOPやIMAPというプロトコルが使われます。POPはメールを端末に取り込んで読み、IMAPはメールをサーバに置いたまま読みます。

POPIMAP
メールの置き場所端末に取り込む(サーバからは消すことが多い)サーバに置いたまま
複数の端末で取り込んだ端末でしか読めないどの端末でも同じメールが見られる
既読などの状態端末ごとにばらばらサーバで共有される
考えてみよう：
パソコンとスマホの両方でメールを見たい人には、どちらが向いている？

IMAPです。メールがサーバに置いたままなので、どの端末から見ても同じメールが見られ、片方で読めばもう片方でも既読になります。POPでも「サーバにメールを残す」設定にすれば、複数の端末で受け取れます。

ドメイン名

IPアドレスのかわりに使う、人にわかりやすい名前。右ほど大きな範囲を表す。

数字のかわりに、名前で指定する

インターネット通信ではIPアドレスを用います。しかし、数字の羅列は人間には覚えにくいので、わかりやすいドメイン名が利用されています。ドメイン名は階層構造になっていて、右側のトップレベルドメインほど大きな範囲を、左側ほどせまい範囲を表します。

考えてみよう：
URL の先頭にある「https」は何を表している？

Webページをやりとりするときのプロトコルです。https は、HTTP に通信の暗号化などのセキュリティを加えたもので、近年は https が多く使われています。

DNS

ドメイン名をIPアドレスに変換するしくみ。DNSサーバが階層ごとに分担して答える。

名前から、IPアドレスを調べる

通信をするときには、インターネット上にあるDNSサーバに問い合わせることで、ドメイン名をIPアドレスに変換します。このしくみをDNS(Domain Name System)とよびます。DNSサーバも階層構造になっていて、上の階層から順に問い合わせていくことで、目的のIPアドレスにたどり着きます。

考えてみよう：
DNSサーバが止まってしまうと、どんなことが起こる？

ドメイン名からIPアドレスを調べられなくなり、URLを入力してもWebページが開けなくなったり、メールが送れなくなったりします。ふだん名前で指定している私たちにとって、DNSは欠かせないしくみです。

Webページが表示されるまで

URLを入力してからページが表示されるまで、次の順にやりとりがおこなわれます。光っている場所が、いま見ているステップです。

入力クライアント(Webブラウザ)に、ドメイン名を含むURLを入力する。
DNSDNSサーバに問い合わせて、ドメイン名をIPアドレスに変換する。
要求調べたIPアドレスあてに、Webサーバへページを要求する。
応答Webサーバが、要求に応じてページのデータを返す。
表示Webブラウザが、受け取ったデータからページを表示する。

電子メールも、クライアントとサーバのやりとり

メールクライアントが SMTP で自分のメールサーバに送り、メールサーバどうしが転送して、宛先のメールボックスに保存します。受信者は POP や IMAP で受け取ります。宛先のメールサーバを探すときにも、DNS が使われています。
